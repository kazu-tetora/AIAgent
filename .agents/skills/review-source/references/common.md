# 言語共通のレビュー基準

## 調査

- 要求仕様、公開インターフェース、互換性の制約を先に確認する。
- 正しさ：正常系だけでなく空入力、境界値、不正入力、状態遷移を追う。
- 回帰：戻り値、永続化形式、呼び出し側が頼る振る舞いを確認する。
- エラー：例外の握りつぶし、途中更新、失敗時のデータ消失を確認する。
- 副作用：入力の破壊、共有状態、資源の解放、同時実行の前提を確認する。
- セキュリティ：入力からファイル・コマンド・秘密情報へ至る経路がある場合に追跡する。
- テスト：実害のある分岐の欠落を確認する。テストが少ないだけでは欠陥としない。

仕様にない制約を追加しない。好みの命名や整形だけの指摘は避ける。同じ原因の指摘はまとめる。未知のコードやテストは副作用を確認してから実行する。

## 重要度

| 重要度 | 判断の目安 |
|---|---|
| P0 | 通常の前提で広範な停止や重大な損失が生じ、即時対応が必要 |
| P1 | 主要機能の停止、データ破損、重大なセキュリティ影響 |
| P2 | 限定した条件で仕様違反や利用者への実害が生じる |
| P3 | 軽微だが具体的な影響が確認できる |

重要度は影響と到達条件で決め、件数を埋めるために指摘しない。静的読解の根拠と実行結果を区別し、未実行の再現手順を実行済みと書かない。
