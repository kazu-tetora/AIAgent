# 指示ファイルの使い分け

| 種類 | 主な対象 | 読まれるタイミング | 向く内容 |
|---|---|---|---|
| `.github/copilot-instructions.md` | GitHub Copilot | 対応機能がリポジトリ文脈を扱うとき | 技術、規約、テスト |
| `AGENTS.md` | Codex 系 | 対象ディレクトリで作業するとき | 作業規約、検証、完了条件 |
| `SKILL.md` | Skill 対応環境 | description と依頼が一致、または明示指定時 | 専門手順、参照資料への導線 |
| 役割プロンプト | サブエージェント | 親が仕事を委譲したとき | 目的、境界、返却形式 |

## 配置

`AGENTS.md` は階層で適用範囲を表せます。ルートに全体規約、特定サブツリーには必要な場合だけ具体的な規約を置きます。

Copilot のリポジトリ指示は `.github/copilot-instructions.md` に置きます。`AGENTS.md` と重なる場合も矛盾させません。

Skill はフォルダ単位です。必須ファイルは大文字の `SKILL.md` です。YAML frontmatter の `name` と `description` が発見・発火に使われます。詳細は `references/`、反復処理は `scripts/`、成果物用素材は `assets/` に分けます。

## 良い指示

曖昧:

```text
きれいなコードを書いて、十分にテストする。
```

観測可能:

```text
標準ライブラリだけを使い、公開関数に型ヒントを付ける。
Python 変更後は `python3 -m unittest discover -s tests -v` を実行する。
```

目的、制約、検証、完了条件の4要素を意識します。

## よくある失敗

- `AGENT.md` や `skill.md` が自動認識されると決めつける。
- すべてを常時指示へ詰め込み、文脈を圧迫する。
- 指示ファイル同士でテストコマンドを矛盾させる。
- 「適切に」「必要なら」だけで判断基準を書かない。
- 実在しないパスやコマンドを書く。
